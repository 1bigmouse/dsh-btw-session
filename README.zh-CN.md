# Btw 临时会话

[English](./README.md) | 中文

在右侧边栏就当前对话提出一次性旁问：**不进入原对话上下文**，单独统计这条侧边
线程的 token 用量，关闭即丢弃，不留任何痕迹。

这是 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）的
第三方插件包（bundle），不属于 DSH 本体。

## 安装

**兼容性**：在 **DSH 0.2.2-rc.5**（桌面版与 CLI）上验证；更早的版本未做兼容，
可能缺少本插件注册的右侧边栏标签页插槽，或图片与按会话作用域取工具所需的接口。

从 GitHub 直接安装：

```sh
dsh plugin --profile <profile> add github:1bigmouse/dsh-btw-session
```

`<profile>` 换成你启动 DSH 时使用的 profile 名：桌面版是 `desktop`，CLI 用户填
`dsh --profile` 后面的名字。桌面版也可以直接在 **插件 → 添加插件** 中粘贴上面的
仓库地址，无需命令行。

想固定到具体某个提交，在地址后面加上提交号：

```sh
dsh plugin --profile <profile> add github:1bigmouse/dsh-btw-session#<sha>
```

也可以克隆仓库后按本地目录安装（桌面版可在 **插件 → 添加插件** 中选择克隆下来的
目录）：

```sh
git clone https://github.com/1bigmouse/dsh-btw-session
dsh plugin --profile <profile> add ./dsh-btw-session
```

这个包是纯 ESM JavaScript，安装后不需要构建，也不涉及 pnpm 的 `allowBuilds`
授权。

## 使用

1. 从右侧边栏的引导中打开 **Btw**，或在输入框输入 `/btw <问题>`，面板会在右侧打开。
2. 在面板自己的输入框里继续追问。每次回答都以当前会话（只读）加上面板内已有的
   问答为上下文，并且可以只读地查看工作区文件。每条回答底部都带复制按钮。
3. 用回形针按钮、粘贴或拖拽附加截图。原对话里已经发过的截图会自动带入，所以
   「这张截图哪里有问题」对打开面板之前发的图同样成立。
4. 对话下方的用量行只统计这条侧边线程——提问数与解码速度，然后是 token 与缓存
   命中率。点击该行可展开完整明细。
5. 没出正文的回答会说明原因（超时／被取消／模型失败／工具轮数用尽／输出截断），
   并给出 **重试** 按钮：它直接重答同一个问题，不用重新输入或重新附图。
6. 点 **关闭并遗忘**（或直接关闭标签页）即丢弃线程；下次打开是空的。

输入框下面那行是**请求预算**，不是进度条：`重放 ≤20 轮 · 上下文 ≤80 条` 表示每条
回答由「面板内最近 20 轮问答」+「原会话最近 80 条消息」拼成。鼠标悬停能看到字符
上限；超出预算时从最早的内容开始丢弃。

工具轮数（`maxToolRounds`）用完后，如果模型还在要求继续读，这些调用**不会执行**
（不能把"结果永远不会到达"的调用写进请求），插件会**再发一次不带工具**的请求让它
基于已读内容作答。因此回答行的轮数可能比 `maxToolRounds` 多一轮；这样产出的回答会
标上「读取轮数用尽」，免得看起来像模型尽力了。

## 不做的事

- 不向原会话写入任何消息、轮次、工具调用或助手消息；侧边线程的任何内容都不会
  成为原会话的模型上下文，它执行的查询也不会向原会话写入 `tool/call` 或
  `tool/result` 事件。
- 只能读。`read`、`glob`、`grep` 使用与会话相同的沙箱和工作目录运行，白名单里
  没有任何能写入、修改、打补丁或执行命令的工具。把 `tools` 设为 `[]` 就只依据
  上下文回答。
- 附件**只收图片**。PDF、源码等原会话里会当作文件上传的内容一律拒绝，因为侧边
  请求只能把模型看得懂的位图交给它。
- 没有子代理、没有审批流程、没有联网工具。
- 不持久化。线程只存在于该会话对应的 Host 进程内存里；关闭面板、刷新页面或重启
  Host 都会丢弃它。图片**字节**是例外，见「安全与隐私」。
- `/btw` 命令本身仍会作为「已运行的命令」记入会话日志，因为运行任何命令都会如此；
  但问题与回答不在记录中。

## 配置

`cordis.patch.yml` 中的 Host 行接受以下字段：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `maxExchanges` | `20` | 新提问时重放的侧边线程历史轮数 |
| `maxContextMessages` | `80` | 单次侧边请求带入的原会话消息数 |
| `maxContextChars` | `48000` | 原会话上下文的字符预算，从最旧的开始丢弃 |
| `maxContextImages` | `3` | 原会话里带入、供模型直接查看的截图数 |
| `maxImages` | `6` | 单个侧边提问可附加的图片数；`0` 表示关闭图片输入 |
| `maxRequestImages` | `8` | 一次请求保留的图片出现次数（从新到旧） |
| `maxOutputTokens` | `8192` | 单条回答的输出上限；推理 token 也计入其中 |
| `tools` | `["read","glob","grep"]` | 侧边回答可调用的只读工具；`[]` 表示仅用上下文回答 |
| `maxToolRounds` | `4` | 允许的工具轮数；用完后会再发一次不带工具的收尾请求来作答 |
| `timeoutMs` | `300000` | 单条回答的实际耗时上限（毫秒）；`0` 表示不设超时 |

行为上还有两点值得知道：

- **只取已结算的上下文**：快照会在第一个「尚未拿到结果的工具调用」处截断。正在跑
  的那一轮还不算对话，排队中未投递的输入同理。
- **失败即一行可重试的记录**：超时、取消、provider 失败、空正文都会在面板里留下一
  条带原因的记录和「重试」。每次尝试带自增序号，迟到的回包不会改写线程。失败的
  尝试也计入用量（那些 token 确实花掉了）。
- **工具调用写成正文时不会被当成回答**：模型可能把工具调用拼成 `< | DSML |` 之类的
  标记写进正文。识别时会先归一化各种「自创分隔符」（制表符竖线、全角竖线、零宽字符、
  全角字母），整条都是标记时按「没给出正文」处理并给重试，绝不把原始标记渲染出来。
| `route` | `null` | 固定的 `{ provider, model }`；默认沿用会话自己的路由 |
| `systemPrompt` | `null` | 替换侧边提问的系统提示词 |

## 安全与隐私

- **没有遥测，也没有自己的服务端。** 每条回答都是一次经会话已配置路由的
  `ctx.llm.stream` 调用；插件不联系其他任何地址，不读取环境变量或凭据存储，也不
  向作者发送任何内容。
- **不落盘。** 线程只存在于 Host 进程内存中，按父会话 id 索引，关闭、刷新或重启即
  删除；问题与回答不会生成文件、数据库记录或会话事件。
- **只读查询。** 只有 `read`、`glob`、`grep` 可以运行，且仅当父会话最后一次请求
  本身提供了这些工具；`maxToolRounds` 限制轮数，白名单之外的调用不会真正执行。
- **路由由框架把关。** 面板通过 DSH 自带认证的 `/api` 通道通信：请求携带浏览器
  的 DSH 会话 Cookie，并通过框架的主机/来源检查后才会进入处理函数。插件本身不加
  token、不加 Cookie、不设置 CORS，也不做来源判断。信任边界是这个 DSH profile 的
  所有者——已受该 profile 信任的页面可以访问其中任意会话 id。
- **回答无法变成代码。** Markdown 以 React 元素渲染，原始 HTML 永不被解释，链接
  与图片地址只允许 `http:`、`https:`、`mailto:`。
- **图片会存下来，线程不会。** 附加的图片经 `ctx.attachments.admitPromptContent`
  写入 DSH 的按内容寻址的附件存储——和普通消息走同一道准入（同样的张数、字节、
  像素与格式上限），因为持久化的 `ImageBlock` 是模型看到图片的唯一途径。关闭面板
  会丢弃线程和其中所有引用，但**已存储的图片字节仍留在附件库里**：本插件没有删除
  接口，也不会另造一个。请把附加的截图视为留在磁盘上，和普通消息里的图片一样。
- **图片路由按线程隔离。** `GET /api/btw/image` 只对「该会话本线程自己准入过」的
  附件 id 返回字节，无法指向别的会话里的对象。

## 开发与验证

```sh
npm test          # 或：node tests/verify.mjs
```

测试用桩 Cordis 上下文同时加载 Host 与浏览器两半，覆盖命令、四条路由、请求组装、
图片准入与请求级图片裁剪、指标折算以及全部客户端注册（标签页类型、引导入口、面板
主体、命令行、关闭处理）。
不需要联网，也不需要安装 DSH，因此同一命令可在 GitHub Actions 的 Node 22 与 24
上运行。
